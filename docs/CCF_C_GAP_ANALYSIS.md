# 面向 CCF-C 类完整论文的证据差距审计

更新日期：2026-08-06

## 1. 结论先行

当前项目已经具备一篇开题报告、学位论文实验章节或短篇机制论文的扎实基础，但**尚不足以稳妥支撑一篇以“普遍提升智能合约模糊测试”为主张的 CCF-C 类完整论文**。

这不是因为运行次数少。项目已有1050份正式日志、30个seed的重复设计、原始日志和校验链，实验执行质量并不差。真正的缺口是：

1. 外部有效性：公开基准仅5个，且经过筛查或适配；
2. 新颖性：状态依赖、调用排序和重复调用已与多项工作明显重合；
3. 语义有效性：当前Harness把多笔交易封装成一笔外层调用，可能改变调用者、原子性和环境语义；
4. 比较充分性：SMARTIAN 已在两个整数属性目标上完成可运行、oracle 对齐的外部基线，但覆盖面仍不足以支撑广泛竞品结论；
5. 可扩展性：开销只在4个很小的合成合约上测量，没有大型真实项目证据。

因此，下一阶段不应继续堆相同合约的seed，也不应立即扩展V2。SMARTIAN 的最小外部基线已经完成；剩余优先级是扩大公开属性任务、补语义适用性和规模证据，或把论文定位收窄为属性定向 Harness 工具/学位论文成果。

## 2. 当前论文最合适的定位

现阶段最可信的定位不是“新的通用智能合约模糊器”，而是：

> 一种面向既有属性模糊器的、属性定向的交易序列Harness合成方法：利用静态状态依赖、简单值约束和有界重复访问，生成可解释的Top-K候选序列，并在不修改Echidna核心的情况下缩小顺序搜索空间。

该定位有四个潜在差异点：

- 目标是用户已经声明的安全属性，而不是一般代码覆盖率或固定漏洞预言机；
- 以外部预处理器和生成Harness的方式复用Echidna，而不是修改其核心执行引擎；
- 输出显式、可审计的候选序列和排名；
- 部署与预处理较轻量。

这些目前只是**候选贡献**，不是已经得到论文证据支持的最终贡献。尤其是“属性定向”和“Harness合成”的文献边界仍需严谨确认。

## 3. 与最相关工作的关系

| 工作 | 与本项目重合 | 当前可能的区别 | 对本项目的要求 |
|---|---|---|---|
| SMARTIAN | 静态数据流预测有效交易序列，并结合动态数据流反馈 | 本项目面向显式属性、输出Echidna Harness、无需修改Echidna核心 | 必须证明属性定向与可移植Harness带来独立价值，而不是弱化版静态序列生成 |
| ConFuzzius | 用动态数据依赖生成更有意义的交易序列 | 本项目不是混合求解器，强调外部预处理与解释性 | 不能把“数据依赖生成序列”本身写成新颖点 |
| IR-Fuzz | 显式考虑函数间数据依赖和调用顺序，并延长调用序列 | 本项目以目标属性裁剪候选，使用Top-K Harness | 必须比较目标导向裁剪与一般覆盖导向排序 |
| MuFuzz | 数据流交易排序、序列感知变异，并依据RAW关系处理重复调用 | 本项目的Repeat与Value机制更静态、更轻量且属性定向 | Repeat和依赖排序不能单独作为核心创新；需正面解释差别并补实验 |
| Harvey | 按需、定向探索交易序列以控制状态空间 | 本项目在模糊测试前生成显式候选序列 | 应讨论离线候选生成与在线按需扩展的取舍 |
| Echidna | 接收用户不变量并随机生成调用序列寻找反例 | 本项目作为其前置序列规划层 | 必须保证Harness执行语义与原始属性测试之间的关系可解释 |

来源：SMARTIAN的官方论文页面说明其静态分析用于构造初始种子、动态数据流用于反馈；ConFuzzius明确使用动态数据依赖生成交易序列；IR-Fuzz和MuFuzz均直接处理调用顺序或序列；Harvey采用按需、定向的交易序列模糊测试。

- [SMARTIAN，ASE 2021](https://pure.kaist.ac.kr/en/publications/smartian-enhancing-smart-contract-fuzzing-with-static-and-dynamic/)
- [ConFuzzius，EuroS&P 2021](https://discovery.ucl.ac.uk/id/eprint/10182330)
- [IR-Fuzz](https://arxiv.org/abs/2301.03943)
- [MuFuzz](https://arxiv.org/abs/2312.04512)
- [Harvey](https://arxiv.org/abs/1905.06944)
- [Echidna官方仓库](https://github.com/crytic/echidna)

### 新颖性风险判断

风险为**高**。如果论文只表述为“使用状态依赖过滤无关交易序列，并允许重复调用”，会被SMARTIAN、IR-Fuzz和MuFuzz直接覆盖。

继续推进的前提，是最终能把贡献收敛为以下更窄命题并提供证据：

> 在不修改既有属性模糊器的前提下，V1可根据目标属性生成可解释、可移植且语义适用范围明确的Top-K交易序列Harness；与非属性定向或等规模候选基线相比，它在一组预先声明的公开属性任务上提高发现深层反例的能力。

若这个命题无法通过文献复核、语义验证和公开实验成立，应及时把目标降为学位论文/工具型成果，而不是继续用更多合成实验包装普遍性。

## 4. 按审稿维度逐项审计

| 审稿维度 | 当前证据 | 判断 | 最低补强 |
|---|---|---|---|
| 问题重要性 | 多交易深层状态是公认问题；现有受控案例清晰 | 基本成立 | 用公开合约案例量化无关序列或目标路径排名问题 |
| 技术新颖性 | Property、Value、Repeat、Top-K Harness已有实现 | 高风险 | 完成相关工作差异矩阵；把创新收窄到属性定向、外置Harness和解释性 |
| 技术正确性 | 受控消融强，候选和日志可追溯 | 部分成立 | 给出算法定义、复杂度、确定性与失败模式；补语义适用性检查 |
| 内部有效性 | 每组30 seed、右删失与多重校正处理规范 | 较强 | 冻结配置，预声明新增实验，不依据结果筛合同或调参 |
| 外部有效性 | 5个公开小型/适配基准 | 不足 | 扩充到项目设定的12–20个合格公开属性任务，并公布纳入流程和全部失败 |
| 基线充分性 | Original、K1/K5、内部组件对照，以及 SMARTIAN 在2个整数目标上的外部对照 | 部分成立 | 扩大到更多 oracle 对齐的公开任务；继续保留等候选规模内部对照 |
| 语义有效性 | 已承认Original与Harness调用语义不同 | 关键缺口 | 静态适用性分类 + 差分执行/反例重放 + 明确不支持特征 |
| 可扩展性 | 4个小合约预处理约1.3秒 | 不足 | 按函数数、依赖边、候选数和路径深度测量分析时间与候选增长 |
| 可复现性 | 日志、解析器、checksum、数据白名单较完整 | 较强 | 补工具版本、运行时镜像/环境、命令和新增输入来源快照 |
| 统计报告 | Wilson、McNemar、Holm、KM、log-rank已实现 | 较强 | 新数据延续配对设计，报告效应量和删失，不只报告p值 |

这里的“12–20个”是本项目在时间限制下设定的最低工作目标，不是任何会议的官方录用门槛。高水平相关工作往往使用几十到上万份真实合约：例如Harvey评估27个真实合约，ConFuzzius使用128个精选合约和21K真实合约，IR-Fuzz使用12K真实合约。规模不可机械横比，但足以说明当前5个公开目标的外推能力很弱。

公开数据来源可以从[SmartBugs Curated](https://github.com/smartbugs/smartbugs-curated)和[DAppSCAN](https://arxiv.org/abs/2305.08456)开始筛查；但它们提供漏洞标签或源码，不必然提供可直接用于Echidna的属性。属性编写必须记录来源、规则和人工工作量，不能依据V1能否成功后再选择性纳入。Trail of Bits还公开了[168个可复用属性](https://blog.trailofbits.com/2023/02/27/reusable-properties-ethereum-contracts-echidna/)，可作为寻找现成属性任务的入口。

## 5. Harness语义是当前最高优先级风险

当前生成方式大致是：Harness部署目标合约，并由一个wrapper在一次外部调用中连续调用目标函数。相比Original Echidna的多笔交易序列，它可能改变：

- `msg.sender`：目标函数看到的是Harness地址；
- 交易边界：多步操作被合并在一笔交易内；
- 回滚范围：某一步失败可能回滚整个wrapper；
- `block.number`、`block.timestamp`及每步环境变化；
- 不同调用者交替执行的场景；
- `msg.value`、payable和资金流；
- 外部调用、重入与多合约交互；
- 外层`Total calls`与目标函数调用量的含义。

这不是写进threats to validity就能结束的问题。如果语义不同恰好使反例出现或消失，成功率比较本身会失去共同测量对象。

最低补强应产生三个输出：

1. `applicability.csv`：逐合同记录上述语义特征，分类为supported、conditional或unsupported；
2. 差分重放：对已知序列以Original多交易方式和Harness方式执行，对比属性相关状态与结果；
3. 反例案例：至少构造或收集一个会因交易边界/调用者变化而产生差异的合同，明确证明方法边界。

## 6. 当前证据可以和不可以写出的主张

### 可以

- V1在六个合成机制基准上能生成有效候选Harness；
- Property、Value和Repeat在各自受控障碍中有可观察作用；
- 在5个经过筛查的公开任务中，K5为149/150，Original为144/150；
- K1存在明确失败案例，说明Top-K选择是实质性风险；
- 当前小型合约上的准备时间约1.3秒；
- 实验数据处理和统计链具备较好的可复现性。

### 不可以

- V1普遍优于Echidna或现有智能合约模糊器；
- 该方法已经解决真实合约中的交易序列爆炸；
- 92到31的候选减少必然导致速度提升；
- Harness与Original处于等价执行语义或等量调用预算；
- 5个公开任务足以代表真实合约生态；
- Repeat、状态依赖排序或交易序列引导本身具有充分新颖性。

## 7. 阶段出口条件

只有满足以下条件，才进入新增正式运行：

- 能用一句话清楚区分本项目与SMARTIAN/MuFuzz；
- 已定义Harness支持、不支持和条件支持的语义范围；
- 新公开基准的筛选规则在看到V1运行结果前冻结；
- 外部基线有可执行、公平的比较口径，或已形成可审计的不可比较结论；
- 新实验的假设、指标、seed、预算和排除规则已经写入manifest。
