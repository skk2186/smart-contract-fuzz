# V1 研究路线与 Go/No-Go 条件

更新日期：2026-08-21。

## 1. 当前决策

- 继续 V1，作为当前论文主线。
- 暂停 V2 作为正式实验主线；保留 V2 代码和失败分析，作为未来增强方向。
- 不再通过增加同一合成合约的 seed 来证明“泛化”。
- 新增工作优先投入公开属性任务、语义适用性、可扩展性和公平基线。

## 2. V1 的准确定位

建议论文定位为：

> 面向既有属性模糊器的属性定向交易序列 Harness 合成方法：利用静态状态依赖、简单值约束和有界重复访问，生成可解释的 Top-K 候选序列，并在不修改 Echidna 核心的前提下缩小顺序搜索空间。

这里的“属性定向”指候选路径终点由用户声明的 Echidna 属性所读取的状态变量决定；不是泛化的漏洞类型识别，也不是覆盖率定向。

## 3. 创新点审计

| 组成 | 单独新颖性 | 可保留的论文价值 | 主要风险 |
|---|---|---|---|
| 状态读写依赖 | 低 | 作为方法基础 | SMARTIAN、ConFuzzius、IR-Fuzz、MuFuzz 已有明显重合 |
| 有界重复调用 | 低 | 证明必要重复路径可被覆盖 | MuFuzz 等已有序列扩展/重复机制 |
| 简单值约束匹配 | 中低 | 解释为什么变量级依赖会错误排序 | 当前只覆盖常量写入和简单 require |
| 属性相关筛选 | 中 | 最重要的差异化候选 | 必须和覆盖/漏洞导向方法做正面对比 |
| 外置 Harness 合成 | 中 | 可移植、可审计、无需修改 Echidna 核心 | wrapper 可能改变调用者、交易边界和回滚语义 |
| Property + Repeat + Value 组合 | 中 | 形成机制分解和可解释排序 | 必须证明不是简单拼装，且每个组件有独立消融 |
| 语义适用性审计 | 中 | 使工具边界可验证、结论更可信 | 它是方法学支撑，不应伪装成性能提升 |

因此，不应使用以下表述：

- 首次使用状态依赖生成交易序列；
- 首次允许重复调用；
- 首次解决状态空间爆炸；
- 普遍优于 Echidna 或现有智能合约模糊器。

## 4. 当前证据

- 六个合成目标：Full-K1 180/180，Original 171/180。
- 四个 Formal 目标：Dependency 92 条候选降到 Property 31 条，减少 66.30%。
- 五个公开 C-1 目标：Full-K5 149/150，Original 144/150，Full-K1 120/150。
- exercise2-access-control 中 Full-K1 为 0/30、Full-K5 为 30/30，证明 Top-K 选择不是细节。
- matched-random 结果支持候选池内排序存在作用，但不能替代外部基线。
- 语义重放验证了 11 条固定成功路径的属性相关最终结果一致，但没有证明 wrapper 与 Original 的完整多交易语义等价。
- SMARTIAN 外部批次只有两个简单整数目标，不能写成广泛 SOTA 排名。

当前结论适合开题、学位论文实验章节或聚焦机制的工具型短文；还不足以稳妥支撑“通用 CCF-C 级方法”主张。

## 5. 研究问题和实验优先级

### P0：恢复对实验的掌控

1. 读取一个合约、一个读写 JSON、一个属性路径 JSON、一个 Full JSON、一个 Harness 和一组原始日志。
2. NoisyFourStep 跑 Original 与 Full-K1，各 1 个 seed。
3. 四个 Formal 主基准各跑 3 个 seed，确认候选路径、编译和日志口径。
4. 只有回归一致后才决定是否扩大到 30 seed。

### P1：证明 V1 的核心机制

- RQ1：Property 是否减少与属性无关的候选路径？
- RQ2：Value 是否纠正 BranchValue 中仅靠变量依赖产生的错误排序？
- RQ3：Repeat 是否覆盖 RepeatedCall 中必须重复访问的路径？
- RQ4：Full-K1/K5 的结果是否由候选排序贡献，而不是任意 Harness 化？
- 必需方法组：Original、Dependency/Property 对照、Value、Repeat、Full-K1、Full-K5、matched-random。

### P2：补 CCF-C 最关键证据

1. 将公开属性任务从当前 5 个扩到至少 12 个；名单、属性、适配和排除规则在运行前冻结。
2. 对每个任务保留 Original、Full-K1、Full-K5，并记录所有失败类别。
3. 扩大至少一个可执行的外部基线；如果无法公平对齐，形成不可比原因和共同 oracle 的替代实验，不伪造横向排名。
4. 在更大合约上记录函数数、依赖边、候选路径数、Slither 时间、Harness 生成/编译时间和路径深度。
5. 保留语义适用性表、差分重放和负面对照。

## 6. V2 的继续条件

V2 只有在以下条件全部满足后才能进入正式比较：

- 六个 V1 回归基准的正确路径仍被生成；
- RepeatedCall 的必要重复未被删除；
- AlternativePath 的多条可行路径未被错误合并；
- MultiProperty 的两个属性仍可分别验证；
- 预先声明的指标相对 V1 有改善；
- 新结果单独存放并有独立方法版本和 manifest；
- 生成器对不支持的 Harness 语义能拒绝或警告。

否则 V2 只保留为未来工作，不再投入新的大批量运行。

## 7. 停止标准

- 四个 Formal 合成基准不再增加超过 30 个 seed。
- 不为修复一个结果而临时改合约、改 K 或删失败日志。
- 若公开任务无法达到至少 12 个支持范围内的预注册任务，应把论文定位收窄为受控机制/工具型成果。
- 若 V1 相对 Original 的收益只存在于合成合约、公开任务不稳定且没有公平外部基线，不声称通用 CCF-C 方法。
- 若 V2 两轮回归仍不能稳定通过，停止 V2 主线，回到 V1 论文整理。

## 8. 版本化要求

每一批新增实验必须记录：

- 方法版本和 commit SHA；
- 固定输入、配置、工具版本和环境；
- seed、预算、timeout、workers、stopOnFail；
- 原始日志及明确完成状态；
- 派生结果的重建命令；
- 纳入、排除和失败原因。

新增实验先进入 work/v1-restart/<run_id>/，通过审计后再提升为正式证据。
